# Sparse encoder bit frequency imbalance 来源审计（Task1–5）

本轮只读已有 seed=1993 的 Task1–5 frozen ViT 训练特征缓存，共 12,500 个样本、25 类、每类 500 个样本。使用原始 Gaussian `R`、`b` 与 exact `k=41` 的稳定排序规则重建 `u=Rh+b`。正式编码器、模型配置、W_B 和训练流程均未改动。

## 数据与统计口径

- `vit_feature_statistics.csv`：768 个 `h` 维度在 12,500 个样本上的总体 mean、population std（`ddof=0`）、min、max。
- `random_projection_statistics.csv`：8,192 个投影 bit 的 `u_i` mean、population std 和 `activation_rate`。`activation_rate` 明确指进入每样本 exact top-41 的比例，不是 `u_i>0` 的比例；后者另存为 `positive_score_rate`。附加 `mean_without_bias`、`bias`、`projection_row_norm` 及离线中心化诊断的 top-k 率。
- `bias_effect.csv`：`freq_without_bias`、`freq_with_bias` 和两者差值均为 12,500 个样本中的**激活次数**，不是比例。仅在离线计算中省略 `b`；正式编码保持不变。
- `sparse_bit_class_distribution.csv`：每 bit × 每类一行，`count` 为该类 500 个样本中激活次数，`class_share` 为该类在该 bit 所有激活中的份额，`activation_rate_in_class=count/500`。从未激活的 bit，其 class share 记为 0。

重建后的每 task、每 bit 激活次数与上一轮 `sparse_bit_frequency.csv` 完全一致。所有方案仍为每样本 41 个 winner；“去 bias”和“中心化”仅用于归因，不作为模型候选。

## 1. ViT 输入分布

`h` 各维标准差中位数为 **1.332**，p99 为 **4.148**，最大 **7.494**；最大约为中位数的 5.63 倍。方差最高的 10/768 维贡献总逐维方差的 **16.31%**。因此存在方差异质性，但并非只有极少数维度承载几乎全部逐维方差；仅从逐维方差也不能推断完整协方差结构。

跨样本均值向量的范数为 **27.76**，样本相对全局均值的平均范数为 **41.91**。这个非零共同均值在随机投影后形成 bit-specific 偏移 `R_i mean(h)`；其跨 bit 标准差为 **27.35**。相比之下，原 `b_i` 的跨 bit 标准差只有 **1.009**。这两者的尺度差异是下面 bias 诊断的关键。

## 2. 投影与 top-k 选择

原编码的累计 winner 次数中位数为 **10/12,500**，p99 为 **796/12,500**，最大为 **3,367/12,500**；1,227 个 bit 从未胜出。若使用频率均匀，每 bit 期望约 **62.56** 次胜出。最频繁的 1% bits 占全部 512,500 次激活的 **19.75%**，远高于均匀时的 1%。

原 winner 频次与 `u` 的无 bias 均值相关：Pearson **0.592**、Spearman **0.900**；与 `u` 标准差的 Pearson 为 **0.224**，与 `R` 行范数的 Pearson 为 **0.062**，与 `b` 的 Pearson 为 **0.017**。相关性并非严格的因果分解，但表明共同均值投影形成的 bit 间位置偏移，比单纯 `R` 行范数或 `b` 更能解释原始 winner 排序。

作为进入 top-k 之前的分数检查，`u_i>0` 比例在各 bit 上的中位数为 **49.70%**，最高频的 82 bits 平均为 **93.44%**。正分数不是 winner 的定义，但这个差异说明候选分数本身已经带有 bit-specific 偏移。

为了隔离共同均值，另计算 **离线反事实** `R(h-mean(h))+b`。这是使用全部 25 类训练数据求均值的诊断，**不是 streaming/no-replay 协议中的合法替代编码器**。结果：

| 离线编码 | 最频繁 1% bits 的激活份额 | 从未胜出的 bits | 最大 winner 次数 |
| --- | ---: | ---: | ---: |
| 原始 `Rh+b` | 19.75% | 1,227 | 3,367 |
| 省略 `b` 的 `Rh` | 19.79% | 1,224 | 3,369 |
| 扣除共同均值的 `R(h-mean(h))+b` | 4.87% | 0 | 622 |

中心化后仅 **37.95%** 的原 winner 保持不变，说明 `R mean(h)` 与 exact top-k 的相互作用是主要集中来源。中心化后仍有 4.87%（而非均匀的 1%）的 top-1% 份额，且其 bit 频率与投影分数标准差 Pearson **0.825**：残余不均与 `R` 对输入变化/协方差的不同响应有关。top-k 把这些连续分数的位置与尺度差异转为离散“入选/落选”，因此是放大机制；不能把不均单独归咎于 top-k，也不能把所有随机投影方向视为等价。

若各 bit 的分数分布在统计上可交换，exact top-k 本身不会长期偏爱固定 bit。这里它放大的是现有的投影分数异质性。

## 3. Bias 的影响

去掉 `b` 后，每样本 top-41 中平均 **97.35%** 的 winner 保持不变；原始与无 bias 的 top-1% 激活份额分别为 **19.75%** 与 **19.79%**。逐 bit 激活次数变化的绝对值中位数为 1，p99 为 36，最大为 165。个别接近胜出边界的 bit 会换位，但 `b` 不是这轮强烈频次不均的主要来源；这与 `b` 跨 bit 标准差仅约为 `R mean(h)` 的 1/27 一致。

## 4. 高频 bits 的类别共享与几何

原编码频次最高的 82 bits 中，**73 个在全部 25 类中都被激活过**；其活跃类别数中位数为 25，归一化类别熵中位数为 **0.905**。这些 bit 广泛共享，但并非在各类完全等频：单个 bit 最大类别份额的中位数为 **13.68%**，高于完全均匀时的 4%。

对 25 类、每类 500 个训练样本，按**不同样本**精确计算期望 sparse cosine（每样本范数平方恒为 41；类间对按 300 个类对等权）：

| 项目 | 全部 8,192 bits | 频次最高的 82 bits 贡献 | 贡献比例 |
| --- | ---: | ---: | ---: |
| 同类 cosine | 0.08199 | 0.03632 | 44.30% |
| 异类 cosine | 0.03859 | 0.02244 | 58.15% |
| 同类减异类 margin | 0.04339 | 0.01388 | 31.98% |

**类别几何判断：** 高频 bits 对异类共同 overlap 的贡献尤其大，说明在 sparse encoder 阶段已经形成跨类别共享背景，可称为几何污染的一个来源。它们同时贡献正的同/异类 margin，不能据此断言这些 bits 完全无类别信息，或单独证明删除它们会提高准确率。这里是训练缓存上 25 类的配对期望，与此前测试集或 5-class-only 几何指标不应直接当作同一数值比较。

## 最终归因

1. **主要来源：ViT 非零共同均值 × 固定随机投影 × exact top-k。** `R mean(h)` 使各投影 bit 获得相差很大的共同分数偏移；top-k 竞争使少数 bit 跨许多样本反复获胜。中心化诊断将 top-1% 激活份额从 19.75% 降到 4.87%，是最直接的定位证据。
2. **次要来源：投影后的样本波动尺度不一。** 中心化后仍有显著频次不均，其频次与投影标准差强相关。ViT 逐维高方差与完整协方差、随机投影方向共同决定这一尺度，不能仅凭本轮把它全归于某几个 ViT 维度或 `R` 行范数。
3. **`b` 非主要来源。** 省略它只更换约 2.65% 的 winner，整体频次集中几乎不变。
4. **模块定位：不均在 encoder 输出时已经存在；memory update 将它转为 W_B column hotspot。** 原频次最高的 82 bits 与 Task5 占用率最高的 82 列重合 **75** 个。上一轮逐位写入审计表明高频 bit 获得更多 plateau-active 写入机会。因此是 **encoder 产生偏置、memory 写入放大其占用效应** 的共同作用；不能把最初 bit 频次失衡归咎于 memory update。

本轮没有调 `k`、`p`、`b` 或其他参数，没有重新训练 W_B，也没有将离线中心化用于正式模型。生成程序为 `tmp/sparse_encoder_bias_audit_compute.py`。输出行数依次为 768、8,192、8,192、204,800；编码频次与已有结果逐列一致。
