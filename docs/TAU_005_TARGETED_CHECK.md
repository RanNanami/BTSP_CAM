# τ=0.005 的定点 current-WB replay-oracle 检查

日期：2026-09-28。结论：在已保存的实验性 k=128/160 `W_B` 轨迹上，`τ=0.005` **逐元素不改变 CA1 support**，但会减小所有正激活的幅度并略微改变 cosine geometry。对分类的影响极小：k128 的 20-task average incremental 改变 **+0.0057 百分点**，k160 改变 **−0.0021 百分点**；两组 Task20 final 均 **0.00 百分点**变化。它不是一个可由本诊断支持的分类收益，也不能据此推断作者用了 `τ=0.005`。

## 1. 实验边界和可复现性

沿用上轮单独保存的 [`tau_oracle_k128/`](../diagnostics/tau_oracle_k128/) 和 [`tau_oracle_k160/`](../diagnostics/tau_oracle_k160/) 中 Task1–20 的 `WB_taskXX.npz`。本轮**没有重新训练、更新或覆盖任何 `W_B`**，没有修改正式 reproduction、默认 config、k、ridge `gamma` 或其他参数。每个 task 使用 current `WB_t` 重新编码所有已见历史**训练** sparse codes，统一重拟合 seen-class ridge，再评估所有已见**测试**类；这是 replay oracle，**不是** exemplar-free 算法。

固定数值 `τ∈{0,0.0025,0.005,0.00625,0.0078125}` 对 k128、k160 都原样使用，**未按 q 对齐**。`τ=0` 与恰好 `τ=1/k` 的点复用上一轮已完整验证的相同 current-WB replay-oracle 输出，并再次用本轮读取的 `W_B`/sparse codes 对密度、均值和分位数做一致性核查；其余点重新拟合 ridge。实现仅在独立 [`run_tau_005_targeted_check.py`](../experiments/run_tau_005_targeted_check.py)，不进入正式路径。完整逐 task 表是 [`tau_005_targeted_check.csv`](../diagnostics/tau_005_targeted_check.csv)，共 **200 行**，每个 `(k,task,τ)` 一行。准确率和比例在 CSV 中以 0–1 表示，`delta_cumulative_pp_vs_tau0` 的单位为**百分点**；`support_difference_count` 是截至该 task 的全部训练与已见测试 CA1 元素合计，另有 train/test 分列。Task1 的 old-class accuracy 为不适用。

## 3. Support 恒等性与幅度变化

因为 `W_B` 和 `s` 为 binary、`s` 恰有 k 个 1，`a=J/k` 且 J 为整数。`τ=0.005` 时，k128 的 `kτ=0.64`、k160 的 `kτ=0.8`，均小于 1；所以 `J≥1` 必为正、`J=0` 仍为零。除数学推导外，脚本还在**每个 task 的所有已见训练和测试元素**上直接比较 `(a>0)` 与 `(max(0,a−0.005)>0)`：

| k | 20 个 task 的 `support_difference_count` | 最大 CA1 密度差 | 最大非零样本比例差 |
|---:|---:|---:|---:|
| 128 | 每 task **0** | **0** | **0** |
| 160 | 每 task **0** | **0** | **0** |

但 feature **不是**逐元素相同。在同一 support 上，`z_0.005=a−0.005·1_{J>0}`。所有 `(k,task)` 的测试均值满足 `mean(a)−mean(z_0.005)=0.005·density(a)`，最大数值残差为 `6.0e-17`。例如 Task20 的两组测试特征已全部非零，k128 `mean_z` 从 0.36150003 降到 0.35650003、p99 从 0.4921875 到 0.4871875；k160 `mean_z` 从 0.38198951 降到 0.37698951、p99 从 0.49375 到 0.48875。Task20 cosine margin 分别从 0.00143772 到 0.00147818、从 0.00109156 到 0.00112062。Task1 也有同 support 下的幅度和 geometry 变化，均逐 task 记录在 CSV。**Support 相同不要求 ridge 权重、logits 或预测相同**；本报告只断言实测的 accuracy 差异很小。

## 4. 跨过 `1/k` 后发生了什么

在严格的 `z>0 ⇔ J>kτ` 规则下，k128 的边界是 `1/128=0.0078125`；k160 是 `1/160=0.00625`。恰好到边界时，`J=1` 从正值变成零。k128 的 `τ=0.00625` 仍在边界下；k160 的 `τ=0.0078125` 已过边界，但尚未达到 `2/160`，所以与 `τ=0.00625` 截断同一组 `J=1`，仅进一步减小保留单元的幅度。

| k、边界 τ | Task1 train+test 改变 support 的元素数 | Task1 test 密度 τ=0 → 边界 | Task1 accuracy Δ | Task5 改变数 | Task10 / Task20 改变数 |
|---|---:|---:|---:|---:|---:|
| 128, 0.0078125 | 52,077（其中 test 22,763） | 98.3906% → 97.2791% | −0.20pp | 4 | 0 / 0 |
| 160, 0.00625 | 15,712（其中 test 7,913） | 98.7018% → 98.3154% | 0.00pp | 0 | 0 / 0 |

因此**边界作用可检测，但主要限于早期**。k128 的 `J=1` support 变化到 Task6 仅剩 1 个元素，Task7 起为 0；k160 到 Task3 尚有 35 个，Task4 起为 0。后期当前 memory 的 overlap 分布已远离 1，跨过该边界不再带来实测稀疏化。k160 从 `τ=0.00625` 到 `0.0078125` 虽保持同一 support，却仍有 Task5 accuracy 90.48%→90.40% 的微小变化，再次说明“相同 support”不等于“相同 readout”。

## 5. `feature-scale / fixed gamma` 的解释边界

当前 ridge 使用固定 `γ=0.1`，无单独截距项。阈值使训练及测试 feature 变化，故 `ZᵀZ`、`ZᵀY`、ridge 权重和 logits 都**允许**变化；上述细小 accuracy 差异与这种 readout 对 feature 数值尺度敏感的机制相容。但是 `z_τ=a−τ·1_{J>0}` 是**按活跃 mask 的减法**，并非统一乘上常数 `c`。Task1 不同样本/维度的 mask 还不相同；即使 Task20 mask 全为 1，也是在每维减去常数。它可改变相对方向、均值与无截距 ridge 的拟合，不能仅凭这五个 τ 点将差异**唯一或主要归因**于“固定 γ 的有效正则化强度”。本轮没有调 γ，也没有做额外的纯缩放对照。

最终判断：`τ=0.005` 在 k128/160 下是**同 support 的幅度扰动**，对 20-task 分类几乎没有稳定影响；跨越 `1/k` 确实改变早期 `J=1` support，但其准确率作用很小且随 task 消失。所有结果仅是 current-WB replay-oracle diagnostic；**不据测试准确率选择正式 τ，也不声称作者使用 0.005**。科研数据表规范用于保持一行一个 `(k,task,τ)` 观测、数值单位和 train/test support 计数口径明确。
